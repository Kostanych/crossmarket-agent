## Поиск и ответ агента (A)

Отложенный тест-сплит: 24 вопроса из 61. Корпус — 199 настоящих карточек ВБ и 700 дистракторов.

| | opus-5 | haiku-4.5 |
|---|---|---|
| верный исход | 1.000 | 0.833 |
| релевантная карточка названа в ответе | 1.000 | 0.636 |
| цены и товары из ответа подтверждены выдачей поиска | 1.000 | 1.000 |
| стоимость вопроса | $0.055 | $0.020 |

Поиск без агента, тот же сплит: recall@1 0.682, recall@5 0.818, MRR 0.783.

В наборе 33 отрицательных вопроса — таких, ответа на которые в корпусе нет. Opus верно
отказал на всех, включая близкие промахи, где рядом в корпусе лежит похожий товар.

Вторая модель показывает, чем платит дешёвая: все провалы haiku — «не пошёл искать», ни
одного «искал и выбрал не то». Из 28 вопросов с ответом в корпусе он вызвал поиск на 21 и во
всех 21 назвал все релевантные карточки, остальные семь искать не стал. Выдуманных цен и
товаров нет ни у одной модели.

Состав текста в векторе выбран замером на корпусе без дистракторов, 28 вопросов:

| состав | recall@1 | recall@5 | MRR |
|---|---|---|---|
| название + характеристики | 0.506 | 0.839 | 0.706 |
| + категория | 0.470 | 0.804 | 0.695 |
| + описание | 0.649 | 0.929 | 0.857 |
| + категория + описание | 0.667 | 0.911 | 0.857 |

Описание даёт около +0.15 к recall@1, категория не даёт ничего, поэтому в векторе её нет. Но
у варианта с описанием фора по построению: вопросы golden-set писались с оглядкой на описания.

## text2sql (C) и роутинг

**text2sql:** результат запроса агента совпал с эталонным на 0.895 из 19 тестовых вопросов,
ни одного неисполнимого запроса. Совпадение считается после нормализации: округление, порядок
строк у неупорядоченных вопросов, лишние колонки. Без послаблений по форме — 0.789. Знание о
схеме подключено скиллом SDK. Со схемой прямо в промпте было 0.947: разница — один вопрос из
девятнадцати, в пределах разброса от прогона к прогону. При этом скилл вдвое дороже, $0.057
против $0.027 на вопрос: его текст дописывается в кэш заново на каждом вопросе.

**Роутинг:** на 27 тестовых однохоповых вопросах первым вызван нужный тул в 1.000 случаев.
Haiku на том же наборе ошибается не маршрутом, а отказом: «бытовые советы не мой профиль» —
и не зовёт ничего.

## Матчинг ВБ ↔ Озон (B)

Отложенный тест-сплит, 61 размеченная пара, среднее трёх прогонов:

| | значение |
|---|---|
| F1 | 0.747 (0.738–0.756) |
| precision / recall | 0.862 / 0.660 |
| «аналога нет»: ни один чужой кандидат не подтверждён | 1.000 (0 из 188) |
| настоящий партнёр дошёл до модели подтверждения | 1.000 |

Кандидатов поиск достаёт без потерь: recall@5 1.000. Треть пар теряется на шаге
подтверждения, потому что в карточке часто нет признака, по которому пару можно отождествить.
Порога по скору кандидатов нет: скор настоящего партнёра 0.831–0.950, топ-1 у товаров без
пары 0.800–0.925, распределения вложены.

Разрыв калибровка/тест — 0.892 против 0.747. Это не переобучение промпта: из 24 карточек, в
которые признаки дописывались руками, 20 лежат в калибровочных парах. Тестовые карточки под
цифру не чинились.

## Судьи

Положительный класс — «плохо»: precision — доля настоящих ошибок среди объявленных судьёй,
recall — доля пойманных.

| судья | что судит | истина | тест | согласие | baseline | precision | recall |
|---|---|---|---|---|---|---|---|
| QA | итоговый ответ агента | ручная разметка | 17 | 0.941 | 0.765 | 0.800 | 1.000 |
| B | вердикт модели подтверждения | метка пары | 61 | 0.770 | 0.656 | 0.769 | 0.476 |
| C | SQL агента и его ответ | эталонный запрос | 76 | 0.882 | 0.908 | 0.000 | 0.000 |

`baseline` — согласие судьи, отвечающего одинаково на всё. Без этой колонки все три цифры
читались бы как успех; с ней видно, что судья C проигрывает вырожденному.

| судья | где ошибается | почему |
|---|---|---|
| B | не ловит ни одного из 5 ложных подтверждений | пара с одним спрятанным отличием: судья видит те же карточки, что тул, и не находит его там же |
| B | пропускает 6 из 16 ложных отказов | в выгрузке нет признака, по которому разметчик отождествил пару; opus вместо sonnet не помогает |
| C | не ловит ни одного из 7 промахов | промах text2sql — правдоподобный запрос с не тем результатом; без исполнения неотличим от верного |
| C | 9 ложных тревог | часть — разные определения: судья оценивает текст ответа, метрика — результат запроса |
| QA | 1 ложная тревога на тесте | придирка к тому, как агент прочёл характеристики карточки |

Итог: прямые метрики первичны. Там, где эталон есть, судья проверяется об него: C проверку
проваливает, B работает на половине ошибок, судья ответов сыграл вничью с проверкой по словам
(0.925 у обоих на всех 40 размеченных).

## Стоимость

Стоимость в отчётах — оценка Claude Agent SDK по прайсу, вшитому в его CLI, а не счёт. Оценка
сверена со счётом Console на 20 вопросах роутинга, прогнанных через API-ключ:

| модель | роль | оценка SDK | счёт Console |
|---|---|---|---|
| opus-5 | оркестратор | $0.68 | $0.68 |
| sonnet-5 | модель подтверждения B | ~$0.34 | $0.23 |
| haiku-4.5 | служебные вызовы CLI | ~$0.06 | $0.06 |
| | всего | $1.08 | $0.97 |

Токены SDK считает точно: у opus совпадение с Console до токена. Расхождение по sonnet —
устаревший прайс: CLI 2.1.233, вшитая в прежнюю версию SDK, считала sonnet-5 по $3/$15 вместо
$2/$10. SDK обновлён, CLI 2.1.259 считает по верному прайсу. Стоимости матчинга и судей,
снятые раньше, по доле sonnet завышены в полтора раза.

Режим аутентификации сдвигает оценку сам по себе: те же вопросы по подписке выходят на 30%
дороже при тех же токенах. Подписка пишет кэш на час, API-ключ — на 5 минут, и часовая запись
дороже. Все замеры проекта сняты по подписке.

Модель подтверждения B — отдельные вызовы SDK изнутри тула. В стоимость запроса оркестратора
они сами не попадают, а в этом прогоне на них пришлась почти треть счёта. Их стоимость и токены
складываются во внешний ответ явно. Задержка на тех же 20 вопросах: p50 10.9 с, p95 21.1 с.

## Observability

`make observe` поднимает Prometheus и Grafana, `make serve` — FastAPI с `/chat`, `/health` и
`/metrics`. На дашборде запросы по исходу, задержка p50/p95, стоимость, вызовы тулов и доля
кэша, рядом метрики, которые Qdrant и ClickHouse отдают сами. Четыре алерта: база недоступна,
расход за час, доля ошибок и обрывов по лимиту, p95 задержки. Вызовы модели подтверждения
ложатся в тот же трейс Langfuse, что и запрос оркестратора.
