# Лог факапов

Случаи, когда система молча делала не то. Планка высокая: рутина сбора данных (съехавший
селектор, сменившаяся кодировка) сюда не идёт — она стоила времени, но ничего не
искажала. Сюда идёт ложноположительный результат или сожжённые впустую деньги. Питает
постмортем в README.

## 1. Инструментирование Langfuse молча не подключилось (26.08.2026, этап 2)

**Что произошло.** Прогон 28 вопросов golden-set отработал, метрики легли в MLflow,
скрипт напечатал «трейсинг Langfuse: включён». Трейсов не появилось ни одного.
Обнаружилось при попытке посмотреть их глазами — уже после того, как прогон был
объявлен закрытым критерием этапа.

**Причина.** Инструментор `openinference-instrumentation-claude-agent-sdk` подменяет
атрибут `query` внутри модуля `claude_agent_sdk.query`. Код агента делал
`from claude_agent_sdk import query` на импорте, то есть замораживал ссылку на исходную
функцию раньше, чем инструментор что-либо подменял. Вызовы шли мимо обёртки, спанов не
создавалось вовсе.

**Почему не заметили.** Проверка была построена на факте «трейс существует»: в Langfuse
лежал трейс `spike_sdk` — но созданный руками, обёрткой вокруг прогона, и содержавший
один пустой спан. Об ошибке не сообщает никто: инструментор не жалуется, что его обошли,
Langfuse не жалуется, что ему не прислали данные.

**Цена.** Прогон за $1.91 без трейсов; чтобы получить их, прогон надо повторить. Метрики
уцелели — они считаются из ответов, а не из трейсов.

**Что изменено.** Функция резолвится поздним связыванием: модуль через
`importlib.import_module`, атрибут `query` — в момент вызова. Плюс `flush_langfuse()` в
конце скрипта: экспорт батчевый, короткий процесс успевал завершиться раньше отправки.

**Вывод.** Критерий «сделано» для наблюдаемости — не «трейс появился», а «в трейсе лежит
то, ради чего он заводился»: спаны тулов, токены, стоимость. Проверять программно
(Langfuse отдаёт трейс по API), а не разглядыванием списка. То же для любого инструмента,
который работает подменой чужих функций: он молчит, когда его обошли.
